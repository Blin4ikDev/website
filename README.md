# Персональный сайт — корабельный пульт

Статический сайт-визитка в эстетике примитивного корабельного интерфейса из
«Проекта „Аве Мария“»: чёрный корпус, белые показания, оранжевые метки и
пастельно-жёлтые аналоговые пометки. Только системный моноширинный шрифт,
чистый HTML, CSS и JavaScript — без сборки, CDN и зависимостей. Публикуется на
GitHub Pages через Actions.

## Что внутри

```
.
├── index.html                   # hero, орбита, монитор сил, обо мне, проекты, навыки, контакты
├── 404.html                     # автономная страница «сигнал потерян»
├── assets/
│   ├── css/terminal.css         # токены, панели, SVG-приборы, адаптив
│   └── js/main.js               # меню, scroll-spy, часы, копирование e-mail, год
├── .github/workflows/deploy.yml # автодеплой на GitHub Pages
├── .nojekyll                    # отключает обработку Jekyll на Pages
└── .gitignore
```

Из чего складывается вид:

- **Чёрно-оранжевая палитра** — почти чёрный фон `#050505`, тёплый белый текст,
  оранжевый `#ff7a18` для активных элементов и пастельно-жёлтый `#e6d59a`
  для вторичных подписей.
- **Крупная моноширинная типографика** — `BLIN4IK` набран жирным моноширинным
  шрифтом, без ASCII-арта и внешних шрифтов.
- **Приборные панели** — плоские рамки, уголки-засечки, сетка и тонкие линии,
  как на простом бортовом дисплее.
- **Орбитальная схема** — встроенный SVG: Солнце, Земля, Тау Кита, оранжевая
  траектория и приблизительная линия Петрова.
- **Монитор сил и ориентации** — встроенный SVG с перекрестием, векторами и
  телеметрией.
- **Строка телеметрии** — маршрут, привод, точка старта и живые часы корабля.
- **Скан-линии** — очень тонкий слой `body::after`, не мешающий чтению.

Поведение:

- фиксированная тёмная тема — переключателя светлой темы нет;
- адаптивная вёрстка и мобильное меню с `Escape` и закрытием по клику вне шапки;
- активный пункт меню подсвечивается при скролле (`IntersectionObserver`);
- кнопка копирования e-mail с запасным сообщением, если Clipboard API недоступен;
- доступность: skip-link, `aria-*`, `aria-current`, видимый фокус, подписи у SVG,
  поддержка `prefers-reduced-motion`;
- никаких растровых изображений, логотипов и внешних ассетов — все схемы
  нарисованы инлайн-SVG;
- относительные пути, поэтому сайт работает и в подпапке
  (`username.github.io/repo/`).

## Локальный просмотр

```bash
python3 -m http.server 8000
# открыть http://localhost:8000
```

Можно просто открыть `index.html`, но локальный сервер ближе к реальным условиям
(например, для `navigator.clipboard` при копировании e-mail).

## Что заменить на своё

| Что | Где |
| --- | --- |
| Ник, роль, описание | `index.html` (`<title>`, `meta`, `.brand`, `.hero`, `.footer`) |
| Текст «Обо мне» и факты | `index.html`, секция `#about` |
| Проекты и ссылки на них | `index.html`, секция `#projects` (`.project__link`) |
| Навыки | `index.html`, секция `#skills` |
| E-mail | `mailto:` и `data-email` в секции `#contact` (сейчас заглушка `hello@example.com`) |
| Соцсети | `href` у ссылок в `.socials` (GitHub и Telegram — проверьте ники) |
| Координаты и маршрут | hero, `.telemetry`, SVG-подписи и `404.html` |

Найти все заглушки сразу:

```bash
grep -rn "hello@example.com\|TODO" index.html README.md
```

Координаты станции и маршрут «SOL → TAU CETI» взяты из оформления, а не из
реальных расчётов. Линия Петрова на схеме приблизительная и нужна только как
графический элемент.

Если сайт живёт в подпапке (`https://username.github.io/repo/`), проверьте ссылки
`/` и `/#contact` в `404.html` — при необходимости замените их на `/repo/` и
`/repo/#contact`.

## Публикация на GitHub Pages

### 1. Создать репозиторий и запушить код

```bash
git add .
git commit -m "feat: ship-console personal website"
git branch -M main
git remote add origin git@github.com:USERNAME/REPO.git
git push -u origin main
```

Имя репозитория влияет на адрес:

- `USERNAME.github.io` → сайт откроется по адресу `https://USERNAME.github.io/`;
- любое другое имя (например, `personal-website`) → `https://USERNAME.github.io/personal-website/`.

### 2. Включить Pages

1. Откройте репозиторий → **Settings** → **Pages**.
2. В блоке **Build and deployment** выберите **Source: GitHub Actions**.
3. Сделайте push в `main` (или запустите workflow вручную: **Actions** →
   «Deploy to GitHub Pages» → **Run workflow**).
4. Через минуту сайт будет доступен по адресу из блока Pages, он же печатается
   в логе job'а.

Репозиторий должен быть публичным (Pages для приватных репозиториев доступен
только на платных тарифах).

### Альтернатива: без Actions

Если не хочется использовать workflow, удалите `.github/workflows/deploy.yml` и в
**Settings → Pages** выберите **Deploy from a branch** → ветка `main`, папка `/ (root)`.
Сайт статический, сборка не нужна.

## Свой домен (по желанию)

1. **Settings → Pages → Custom domain** — введите домен.
2. В DNS пропишите `CNAME` на `USERNAME.github.io` (или `A`-записи на IP GitHub Pages).
